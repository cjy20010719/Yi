# 本地一键发布

需要 macOS、Command Line Tools、Python 3、Node.js 18+（只用于发布时独立验证公钥签名，无 npm 依赖）、已登录的 Git HTTPS 凭证，以及原来的 Yi EdDSA 私钥。不要创建新的签名密钥来替换原私钥。

1. 提交已检查的功能代码、`docs/release-v版本.md` 发布说明，确认工作区干净且 main 已推送。
2. 后续版本从 `1.0.1` 递增，运行对应的 `zsh scripts/release.sh` 命令。版本必须递增，内部构建号自动加一。
3. 本地生成 Universal 应用、DMG/ZIP、校验和，运行回归测试，签名包和 appcast，发布 GitHub Release，最后把签名 appcast 推送到 docs/，由免费 GitHub Pages 部署。
4. 确认 Pages 部署成功，在旧版 Yi 中检查更新。不要把测试版加入正式 appcast。

签名读取顺序：`YI_ED_KEY_FILE` 指定的本地文件 → 仓库外 `../Yi-private/sparkle-ed25519.key` → 本机钥匙串的 `Yi-release` 账户。备用文件和目录权限分别为 600 和 700。私钥不会传入命令参数、GitHub Secrets、CI 或 Git。请自行离线安全保管；丢失后无法为已安装用户安全地直接轮换公钥。

Sparkle 固定版本与官方包校验值在 `scripts/fetch-sparkle.sh`。升级 Sparkle 时必须重新核实官方稳定版本、SHA-256 和发行说明。

## 中断恢复

流程只允许上传固定五个文件：当前版本 DMG、ZIP、安装说明、SHA256SUMS、签名 appcast。上传完成后对比 GitHub 返回的 SHA-256 与本地文件。匹配的 draft 可重复执行上传；不会覆盖不同内容，也不修改已发布安装包。

如果上传中断，保留当前 dist/ 文件，重跑：

```sh
python3 scripts/publish-release.py --notes docs/release-v1.0.1.md
python3 scripts/publish-release.py --notes docs/release-v1.0.1.md --publish
cp dist/appcast.xml docs/appcast.xml
git add docs/appcast.xml
git commit -m 'Publish signed update feed for 1.0.1'
git push origin main
```

如果只有 appcast 推送失败，先确认 Release 已公开，再重做最后的复制、提交与推送。旧 feed 始终有效，新包未公开时不应提前改正式 feed。签名后不能编辑 XML，任何修改都必须重新签名。不要重复构建同一个已发布版本并替换附件。

## 免费签名的边界

EdDSA 验证发布者及下载完整性，Apple 临时签名维护包结构完整性，两者都不等于 Developer ID 或 Apple 公证。新用户可能要按系统流程允许首次打开。无固定 Developer ID 的签名身份，macOS 可能在每次更新后要求重新添加辅助功能和屏幕录制权限；没有通过削弱签名规则、修改 TCC 数据库或关闭系统保护来规避。程序偏好保留，但系统隐私授权无法由应用自行备份和恢复。

正式版本必须递增；当前正式版本为 1.0.0，下一版本为 1.0.1。相同版本的安装不会触发更新。

## 重复完整更新测试

`python3 scripts/prepare-update-smoke.py` 会在 dist/ 下建立唯一测试目录，编译隔离的 1.0.0/100 和 1.0.1/101 测试应用，使用同一 Sparkle 和更新公钥，生成签名 feed 与包。按输出命令运行仅绑定 127.0.0.1 的服务器，用 Finder 打开测试应用，点击「检查更新」→「安装更新」→「安装并重新启动」。核对窗口版本、安装后 plist 和 launches.txt。测试不会替换正式应用，也不会使用正式偏好域。HTTP/ATS 例外仅写入测试 bundle。

篡改 XML 文本且不重新签名，再检查更新，应提示 feed 签名无效并拒绝；恢复合法 feed 后可测试破坏 ZIP 内容是否被拒绝。不要为“通过测试”关闭签名检查，也不要把测试 feed 上传到正式 Pages。
